# Тестовое задание: канвас на React Flow

Редактор с нодами «текст → генератор → результат». Бэкенд готов, фронтенд — в `apps/web` (`@canvas/web`).

## Запуск

Потребуются Node.js 24.x и npm 11.x.

```sh
npm ci
```

Терминал 1 — API:

```sh
npm run dev
```

Терминал 2 — фронтенд:

```sh
npm run dev:web
```

Приложение: [http://127.0.0.1:5174](http://127.0.0.1:5174). API: [http://127.0.0.1:4001](http://127.0.0.1:4001), Swagger: [http://localhost:4001/docs/](http://localhost:4001/docs/).

Сборка фронтенда: `npm run build:web`. Адрес API: `VITE_API_URL`.

## Архитектура

FSD: `app → pages → widgets → features → entities → shared`.

- `shared/api` — подготовка запроса, `fetch`, разбор тела и ошибки разделены. Компоненты получают типизированные данные.
- `entities/graph` — граф, ETag, сериализация без служебных полей React Flow.
- `features/save-graph` — debounce 500 мс и очередь PUT, чтобы старый ответ не затирал новые правки.
- `features/run-generation` — перед запуском flush сохранения, опрос статуса, повтор по Idempotency-Key.

## Обработка данных

Сериализация графа (`toApiGraph`) вызывается на каждое сохранение, не на каждый кадр перетаскивания. Один проход по нодам и один по связям, без `map().filter()` и без полей `selected` / `dragging`. Проверка связи строит `Map` нод один раз и одним проходом по рёбрам отклоняет лишний вход или второй выход генератора.

## Проверенные сценарии

- Создание пространства, три типа нод, связи только текст → генератор → результат.
- Автосохранение после паузы, генерация сразу после правки дожидается PUT.
- Успех и тестовый отказ, повтор, восстановление после перезагрузки.
- Конфликт 412 оставляет черновик и предлагает перечитать сервер.

## Известные недоработки

- Нет списка нескольких пространств в UI: повторно открывается последнее сохранённое.
- Совместное редактирование и undo не делались — в задании не требуются.
